# Audit technique du 12 septembre 2026

Audit réalisé par quatre agents : intégration/qualité, simulation TypeScript, Pixi et portabilité. Point de départ : `a7229fa`. Les corrections ci-dessous ont été appliquées puis confrontées aux tests. Ce rapport distingue le jeu web corrigé des fonctions qu’il reste à construire avant un port natif.

## Corrections vérifiées

| Domaine | Défaut observé | Correction et preuve |
| --- | --- | --- |
| Navigation | Une destination `NaN` faisait boucler `findPath` indéfiniment. | Rejet des coordonnées non finies avant calcul ; visibilité bornée et ordres antérieurs préservés. Régression exécutée dans un sous-processus avec délai maximal. |
| Économie humaine | Le sabotage d’une route retirait ses paysans vivants sans crédit de remplacement. Après réparation, zéro vivres pouvait empêcher définitivement leur retour. | Crédit des paysans déplacés conservé. Tests de sabotage et capture, réparation/reconquête sans stocks, puis livraisons effectives. Les plafonds et délais de recrutement restent appliqués. |
| Ordres | Défendre, piller ou récolter pouvaient contourner la provocation. Des ordres refusés pouvaient créer un marqueur d’attaque. | Validation cohérente de toutes les voies ; seules les unités libres répondent. Les groupes partiels reçoivent le véritable motif de refus. |
| Garnisons | Une attaque individuelle pouvait être refusée à un soldat en tour parce qu’il ne faisait pas partie de l’armée itinérante. | Validation de la cible séparée de celle de l’armée globale. Test de sortie d’une tour vers une propriété et une route. |
| Circulation | La liste des acteurs était reconstruite et leur camp rescanné pour chaque voisin. | Parcours direct des alliés, sans tableau combiné temporaire ; distance restante de l’acteur calculée une seule fois. |
| WebGL | Après perte puis restauration du contexte, la texture calculée du terrain devenait vide. | Arrêt du rendu pendant la perte, régénération après restauration Pixi. Test réel `WEBGL_lose_context` : les **2 290 598 pixels visibles** du terrain sont retrouvés. |
| Mémoire | Les masques de sélection conservaient quatre canaux RGBA alors que seul l’alpha était utilisé. | **132,1 → 33,0 MiB** pour ces masques CPU, soit **99,1 MiB économisés**. Picking précis vérifié ; sources et textures GPU inchangées. |
| Affichage | Changer de densité d’écran sans changer la taille CSS conservait l’ancien buffer. | DPR réévalué au prochain rendu, toujours plafonné à 2. Test : buffer de 1024 à 2048 pixels lors du passage DPR 1 → 2. |
| Entrées | Une capture de pointeur perdue pouvait laisser un geste actif. | Annulation sur `lostpointercapture`, libération des captures à la destruction. |
| Aperçus | Le composant Sprite traitait toutes les animations comme une bande horizontale. | Découpage partagé avec la carte ; la seconde rangée de l’animation de mort est effectivement lue. |
| Clavier | Ctrl/Cmd/Alt + chiffre pouvait recruter avant le raccourci navigateur ; Ctrl/Cmd + R pouvait rappeler l’armée. | Les modificateurs sont filtrés avant les commandes métier. Test navigateur : aucun achat avec les trois modificateurs, recrutement toujours possible avec le chiffre seul. |
| Chargement React | Une erreur du module différé laissait la racine vide. | Frontière d’erreur avec message et bouton de rechargement. Test par indisponibilité temporaire du module puis retour du serveur. |
| Préchargement WebKit | Un module JS indisponible restait en échec après rafraîchissement, même après un vrai HTTP 503 temporaire sans cache. | `modulePreload: false` évite le cache défectueux. Rechargement testé après panne réseau et 503 sur Chromium et WebKit ; les CSS restent préchargées. |
| Réglages audio | Stockage refusé ou quota atteint : la sourdine et les volumes pouvaient se perdre entre écrans. | Repli mémoire validé pour la session, sans écraser le choix avec une ancienne valeur persistée. Tests PC/mobile, stockage refusé, quota, récupération, valeurs externes et données invalides. |
| Activation tactile audio | Le jeu n’écoutait que `pointerdown` et le clavier. | Ajout du `click` synchrone, complément utile à l’activation tactile WebKit. Aucun changement des pistes ni des règles de fondu. |

Le microbenchmark de circulation mesure `walk` sur 1 500 passes, médiane de cinq essais locaux : **66 → 24 ms** pour 30 alliés/15 ennemis et **248 → 98 ms** pour 60/30. Il isole cette fonction ; il ne mesure ni les FPS du jeu complet ni les performances d’un iPhone.

Le défaut de préchargement correspond au [bug WebKit 270357](https://bugs.webkit.org/show_bug.cgi?id=270357), encore ouvert à la date de l’audit. Désactiver ce préchargement ajoute potentiellement une étape réseau au premier accès au jeu : Game puis sa dépendance sont chargés à la demande. La récupération après panne est vérifiée ; aucun gain de temps de chargement n’est revendiqué pour ce réglage.

## Nettoyage et contrôles durables

- **56 fichiers inutilisés retirés** : 55 composants de scaffolding et le hook associé. Les cinq composants réellement employés restent présents ; leurs fonctions/exportations inutilisées sont retirées.
- **Neuf dépendances d’exécution retirées** : `@shadcn/react`, `cmdk`, `date-fns`, `embla-carousel-react`, `input-otp`, `react-day-picker`, `react-resizable-panels`, `recharts`, `shadcn`. Les variantes d’état utilisent maintenant la syntaxe native de Tailwind ; la licence MIT des composants est conservée dans le paquet.
- Knip ajouté et configuré pour l’application, les styles, scripts et fixtures. Le contrôle passe sans fichier, export ou dépendance inutilisé signalé. Trois exceptions de résolution documentées concernent uniquement les modules virtuels Vite du test Pixi.
- `MANOR_TIERS` supprimé, branches identiques/inaccessibles simplifiées, exports internes retirés. Aucune ressource dynamique n’a été supprimée uniquement parce que son nom n’apparaissait pas dans un import JavaScript.
- TypeScript strict conservé ; `noUnusedLocals` et `noUnusedParameters` ajoutés ; `allowJs` retiré du périmètre de compilation TypeScript. Aucun contournement global de lint ajouté.
- Playwright verrouillé dans les dépendances de développement. Les contrôles n’exigent plus de retrouver un runtime externe.
- Tests obsolètes remis en phase avec les vrais parcours : mission, recherche gobeline, annulation de construction et roue du manoir. Ils vérifient les durées et les dépenses, au lieu d’attendre des améliorations instantanées ou un ancien `rallyPoint`.
- Artworks déplacés de `public/menu/` vers `art-source/menu/exports/`. Les originaux et leur outil d’export sont conservés hors du build ; **447 256 octets** de WebP inactifs ne sont plus distribués. Favicon SVG inutilisé retiré. Documentation du jeu réécrite autour de l’état actuel.

Le CSS du build de contrôle représente **128 776 octets** sur deux feuilles. Le dossier public après nettoyage représente **65 804 650 octets**, majoritairement des musiques chargées séparément ; ce n’est pas le poids du premier écran.

Vite passe de **8.0.13 à 8.0.16**, correctif de la même série pour les avis de sécurité Windows. Les conditions d’exploitation concernent le serveur de développement exposé ; le projet reste lié à `127.0.0.1`. L’audit npm initial signalait deux paquets vulnérables, Vite et Undici. Après correction et retrait du générateur inutilisé, **`npm audit` ne signale plus de vulnérabilité** au 12 septembre 2026. Son graphe passe de 562 à 248 dépendances, en incluant les variantes optionnelles de plateformes. [Avis Vite](https://github.com/vitejs/vite/security/advisories/GHSA-fx2h-pf6j-xcff).

## Validation

Les contrôles s’exécutent aussi sur les pull requests vers `main`. Le job de build a uniquement le droit de lecture du dépôt ; le job de publication distinct ne reçoit ses droits Pages qu’après succès du build, et uniquement sur `main`. Le checkout ne conserve pas ses identifiants. Cette séparation suit les [workflows Pages officiels](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

La chaîne GitHub Pages exige désormais : installation verrouillée, audit de sécurité au seuil élevé, tests, lint avec types, Knip, build et contrôle navigateur du paquet sur Chromium et WebKit. Le contrôle sert `dist` sous `/portable/`, refuse toute requête externe dans les parcours normaux et vérifie les ressources sous ce préfixe.

Résultats locaux :

- **238 tests de simulation réussis**, dont neuf nouveaux scénarios de régression.
- TypeScript, Oxlint et Knip réussis.
- Contrôles Pixi, cycle de vie GPU, multirangs, densité, commandes et destruction réussis.
- Mission et conquête réelles : desktop, 390×844, 320×568, 844×390.
- Recherche gobeline, annulation de placement, bestiaire et roue temporisée : réussis.
- Stockage audio refusé/quota/récupération : réussi sur PC et téléphone simulé. Le même script fait partie du contrôle du build compilé.
- Tactile complet : 390×844, 320×568, 844×390, 768×1024, 1024×768, 1180×820 et vérification desktop 1280×800 ; sélection, pan/pinch, ordres, recrutement, construction, récolte, rotation et paramètres réussis.
- Menu et musique : quatre formats de menu, puis retour/reprise/rafraîchissement/sourdine sur PC, téléphone et tablette, avec et sans autorisation de lecture automatique.

Les scénarios ne prétendent pas parcourir toutes les parties possibles. La couverture mécanique est complétée par de vrais parcours navigateur ; aucune conclusion de performance matérielle ne repose uniquement sur une simulation de viewport.

## Portabilité et dette restante

La cible est explicitement **iOS/iPadOS 16.4+, Safari 16.4+, Chrome/Edge 111+, Firefox 128+**. Elle découle des fonctionnalités requises par Tailwind 4, Vite et le tag utilisé de Base UI. Le jeu n’exige pas de serveur métier et le moteur ne dépend pas du DOM : le même cœur peut être conservé pour un conteneur iOS ou desktop. [Compatibilité Tailwind](https://tailwindcss.com/docs/compatibility), [analyse détaillée iOS et Steam](audit-portability.md).

Travaux nécessaires avant un véritable port :

1. **Sauvegardes versionnées et migrations.** « Reprendre » garde uniquement la page vivante. Tester reprise après fermeture forcée, corruption et mise à jour avant de promettre une reprise native fiable.
2. **Packaging et cycle de vie.** Projet iOS signé, intégration du cycle natif, tests d’interruption audio, puis exécutable desktop entretenu et installation Steam. Aucun de ces paquets n’est fabriqué par cet audit.
3. **Budget matériel.** Profiler GPU, mémoire totale et longues sessions sur appareils réels. Les bandes de 4608/5120 px demanderaient un atlas adapté sur un appareil limité à `MAX_TEXTURE_SIZE=4096`. Les 99,1 MiB économisés concernent seulement les masques CPU.
4. **Steam Deck et accessibilité.** Manette, focus, indications adaptées, lisibilité à 800p, performances et veille/reprise à valider sur le Deck. L’interface tactile ne suffit pas à établir le badge Verified.
5. **Droits des ressources.** La police intégrée est une démo personnelle ; vérifier la licence d’intégration. Compléter les preuves pour les six MP3 fournis. Ce constat n’affirme pas que l’utilisateur ne possède pas les droits ; le dépôt ne les démontre pas.
6. **Architecture des prochaines cartes.** Extraire les définitions de carte et les modèles partagés ; migrer les tâches vers des unions discriminées et réduire les imports circulaires par étapes. `Game.tsx` et le moteur restent volumineux. Toute découpe doit conserver les scénarios de gameplay. Profiler les copies de snapshots avant d’optimiser le store.

Aucune réécriture générale du moteur, migration WebGPU, substitution de police, modification de dessin ou nouvelle dépendance native n’a été faite sans besoin démontré. Les limites précédentes restent des travaux identifiés, pas des compatibilités certifiées.
